### 1. Verification Summary & Runtime Architecture Verdict

For a 30-to-48-hour hackathon, selecting the on-device AI runtime involves balancing **inference latency** against **setup velocity**:

| Evaluation Aspect | Qualcomm AI Engine Direct (QNN / QAIRT / GenieX) | llama.cpp (CPU Backend + ARM I8MM) | PyTorch ExecuTorch |
| :--- | :--- | :--- | :--- |
| **Compute Target** | Hexagon NPU (HTP v81) | **Oryon CPU (ARM NEON + I8MM)** | CPU / XNNPACK (QNN delegate experimental) |
| **Hackathon Setup Cost** | **Very High**: Requires QAIRT SDK, native `.so` libs, and pushing unsigned skeleton libs to `/vendor/` (requires root/unlocked bootloader). | **Low**: Single C++ `.so` via Android NDK; zero root or vendor modifications needed. | **Medium-High**: Heavy Python model export pipelines and framework boilerplate. |
| **Model Compatibility** | Proprietary Context Binaries (`.bin`); W8A16 quantized. No native GGUF INT4 path. | **Universal GGUF** (Q4_K_M, Q4_0, Q8_0); huge community ecosystem. | `.pte` ExecuTorch programs. |
| **Real-World Tokens/Sec** | **40–60 tok/s** (Theoretical NPU maximum for small models, but tooling is immature). | **8–16 tok/s** on Oryon CPU. (Note: Vulkan/OpenCL on Android often regresses to 1–3 tok/s). | 5–10 tok/s on CPU. |
| **RAM Footprint (INT4)** | ~1.6 GB (W8A16 is larger) | **~1.8–2.4 GB** (Weights + KV-Cache for 2K context) | ~2.5–3.0 GB (Framework overhead) |
| **Hackathon Verdict** | High Risk for 30h Hackathon | **🏆 Recommended Winner (Maximum Velocity & Zero Driver Regressions)** | Secondary Alternative |

#### The Empirical GPU vs. CPU Finding:
Multiple Android benchmarks demonstrate that **mobile GPU / Vulkan backends for `llama.cpp` often perform worse than CPU on Android** (dropping to ~1–3 tok/s due to driver dispatch overhead and memory synchronization).  
By compiling `llama.cpp` for the **Oryon CPU using ARMv8.6-A I8MM (Integer Matrix Multiply)**, you get rock-solid stability, zero driver crashes, and sustained **8–15 tokens/second** on 1.5B–3B models.

### 2. CMake & NDK Configuration for Oryon CPU (`CMakeLists.txt`)

In `app/src/main/cpp/CMakeLists.txt`, configure llama.cpp for native ARM NEON + I8MM acceleration without flaky Vulkan/OpenCL dependencies:

```cmake
cmake_minimum_required(VERSION 3.22.1)
project(bimax_llama_jni)

set(CMAKE_CXX_STANDARD 17)

# Target ARMv8-A with NEON and dot-product / I8MM acceleration
set(CMAKE_C_FLAGS "${CMAKE_C_FLAGS} -O3 -flto -march=armv8.2-a+dotprod+i8mm")
set(CMAKE_CXX_FLAGS "${CMAKE_CXX_FLAGS} -O3 -flto -march=armv8.2-a+dotprod+i8mm")

# Include llama.cpp source files
add_subdirectory(${CMAKE_CURRENT_SOURCE_DIR}/llama.cpp llama_build)

# Create JNI wrapper library
add_library(bimax_llama SHARED
    llama_jni_bridge.cpp
)

target_include_directories(bimax_llama PRIVATE
    ${CMAKE_CURRENT_SOURCE_DIR}/llama.cpp/include
    ${CMAKE_CURRENT_SOURCE_DIR}/llama.cpp/common
)

target_link_libraries(bimax_llama
    llama
    common
    log
)
```

### 3. Model Storage Strategies in `context.filesDir`

Native C++ `mmap()` cannot directly memory-map files inside compressed APK assets. Quantized models must reside on the internal filesystem (`context.filesDir` / `/data/data/<package>/files/`).

#### Strategy A: Pre-Bundle Model in `assets/` and Unpack on First Launch
Ideal for smaller 1.5B models (`~1.1 GB`) bundled with the APK:

```kotlin
package com.bimax.mobile.ai

import android.content.Context
import java.io.File
import java.io.FileOutputStream

object AssetModelLoader {

    fun ensureModelAvailable(context: Context, assetName: String, targetFileName: String): File {
        val target = File(context.filesDir, targetFileName)
        if (target.exists() && target.length() > 100_000_000L) {
            return target // Already extracted
        }

        context.assets.open(assetName).use { input ->
            FileOutputStream(target).use { output ->
                val buffer = ByteArray(64 * 1024)
                while (true) {
                    val read = input.read(buffer)
                    if (read == -1) break
                    output.write(buffer, 0, read)
                }
                output.flush()
            }
        }
        return target
    }
}
```

#### Strategy B: Dynamic Runtime Download with OkHttp Streaming
Ideal for 3B models (`~1.9 GB`) downloaded on first launch with progress indicators:

```kotlin
package com.bimax.mobile.ai

import android.content.Context
import kotlinx.coroutines.Dispatchers
import kotlinx.coroutines.withContext
import okhttp3.OkHttpClient
import okhttp3.Request
import java.io.File
import java.io.FileOutputStream
import java.io.IOException

object DynamicModelDownloader {

    suspend fun downloadModel(
        context: Context,
        modelUrl: String,
        targetFileName: String,
        onProgress: (percent: Int) -> Unit
    ): File = withContext(Dispatchers.IO) {
        val target = File(context.filesDir, targetFileName)
        if (target.exists() && target.length() > 500_000_000L) {
            return@withContext target
        }

        val client = OkHttpClient()
        val request = Request.Builder().url(modelUrl).build()

        client.newCall(request).execute().use { response ->
            if (!response.isSuccessful) {
                throw IOException("Model download failed with HTTP ${response.code}")
            }

            val body = response.body ?: throw IOException("Empty response body")
            val totalBytes = body.contentLength()

            body.byteStream().use { input ->
                FileOutputStream(target).use { output ->
                    val buffer = ByteArray(64 * 1024)
                    var bytesRead: Int
                    var totalRead = 0L

                    while (input.read(buffer).also { bytesRead = it } != -1) {
                        output.write(buffer, 0, bytesRead)
                        totalRead += bytesRead
                        val percent = ((totalRead * 100) / totalBytes).toInt()
                        onProgress(percent)
                    }
                    output.flush()
                }
            }
        }
        target
    }
}
```

### 4. Hardware-Aware Kotlin Wrapper (`LocalModelEngine.kt`)

```kotlin
package com.bimax.mobile.ai

import android.content.Context
import kotlinx.coroutines.Dispatchers
import kotlinx.coroutines.withContext
import java.io.File

class LocalModelEngine(private val context: Context) {

    private var isInitialized = false

    suspend fun initialize(modelFile: File): Boolean = withContext(Dispatchers.Default) {
        if (!modelFile.exists()) return@withContext false

        // Snapdragon 8 Elite Oryon core assignment:
        // Use 6 performance threads (3.62 GHz), keeping the 2 Prime cores (4.6 GHz) free for UI/network
        val threads = 6

        val status = nativeInitModel(
            modelPath = modelFile.absolutePath,
            nThreads = threads,
            contextSize = 2048
        )
        isInitialized = (status == 0)
        isInitialized
    }

    suspend fun infer(prompt: String, maxTokens: Int = 150): String = withContext(Dispatchers.Default) {
        if (!isInitialized) throw IllegalStateException("Model is not initialized")
        nativeInfer(prompt, maxTokens)
    }

    private external fun nativeInitModel(modelPath: String, nThreads: Int, contextSize: Int): Int
    private external fun nativeInfer(prompt: String, maxTokens: Int): String

    companion object {
        init {
            System.loadLibrary("bimax_llama")
        }
    }
}
```
