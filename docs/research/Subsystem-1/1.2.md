### 1. Verification Summary & Technical Verdict

Every technical claim in this research dossier has been audited against Cloudflare Zero Trust API documentation, RFC 6750 / RFC 9207 specifications, and Android security best practices:

1. **Edge Service Token Verification**: Validated. Cloudflare Access evaluates `CF-Access-Client-Id` and `CF-Access-Client-Secret` at edge POPs (Point of Presence) **before** traffic reaches the tunnel or origin. If credentials fail or are omitted, traffic is terminated at the edge.
2. **WebSocket Handshake Compatibility**: Validated. RFC 6455 specifies that WebSockets initiate via a standard HTTP/1.1 `GET` request containing `Upgrade: websocket` and `Connection: Upgrade`. Any headers configured in the HTTP request builder are evaluated by Cloudflare Access during this initial upgrade phase.
3. **401 Unauthorized Response Behavior**: Validated. For machine-to-machine and programmatic endpoints, Cloudflare Access returns `HTTP/1.1 401 Unauthorized` with a `WWW-Authenticate: Bearer realm="OAuth", error="invalid_token"` header rather than a 302 redirect to an HTML login portal.
4. **Service Tokens vs. mTLS Trade-Off**: Validated. For a 30-to-48-hour hackathon, **Service Tokens + Android Keystore + E2EE** is the optimal strategy. mTLS introduces complex PKI tooling (custom CA, certificate signing, Android KeyChain / `SSLSocketFactory` configuration). Since Bimax uses **Noise Protocol E2EE at the application layer**, Service Tokens at Layer 1 provide edge protection without slowing down development.

### 2. Cloudflare Zero Trust Dashboard Configuration

Follow these exact steps in the Cloudflare Zero Trust dashboard to configure Service Auth:

#### Step A: Generate the Service Token
1. Navigate to **Zero Trust** $\rightarrow$ **Access controls** $\rightarrow$ **Service credentials** $\rightarrow$ **Service Tokens**.
2. Click **Create Service Token**.
3. Name: `bimax-android-client`.
4. Service Token Duration: Select **Non-expiring** (or set to 1 year for demo).
5. **CRITICAL**: Copy the **Client ID** and **Client Secret** immediately. (The secret is displayed only once).
   - Format: `xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx.access`

#### Step B: Attach Service Token to Access Application
1. Navigate to **Zero Trust** $\rightarrow$ **Access** $\rightarrow$ **Applications**.
2. Click on your tunnel application (e.g., `bimax-bridge.yourdomain.com`).
3. Under the **Policies** tab, click **Add a policy**:
   - **Policy Name**: `Allow Android Service Token`
   - **Action**: `Service Auth`
   - **Session Duration**: `Same as application session` (or `No session / default`)
4. In the **Configure an include rule** section:
   - **Selector**: `Service Token`
   - **Value**: Select `bimax-android-client`.
5. Save the policy.

### 3. Production Android Kotlin Code Implementation

To prevent security vulnerabilities, **never hardcode the Client Secret in plaintext string resources or BuildConfig**. Instead, store it using **Android Keystore-backed `EncryptedSharedPreferences`** and inject it dynamically into OkHttp using an `Interceptor`.

#### A. Secure Token Storage Manager (`TokenStore.kt`)

```kotlin
package com.bimax.mobile.security

import android.content.Context
import androidx.security.crypto.EncryptedSharedPreferences
import androidx.security.crypto.MasterKey

class TokenStore(context: Context) {
    // Hardware-backed MasterKey using Android Keystore (StrongBox / TEE)
    private val masterKey = MasterKey.Builder(context)
        .setKeyScheme(MasterKey.KeyScheme.AES256_GCM)
        .setRequestStrongBoxed(true) // Falls back to standard TEE if StrongBox is unavailable
        .build()

    private val prefs = EncryptedSharedPreferences.create(
        context,
        "bimax_secure_credentials",
        masterKey,
        EncryptedSharedPreferences.PrefKeyEncryptionScheme.AES256_SIV,
        EncryptedSharedPreferences.PrefValueEncryptionScheme.AES256_GCM
    )

    fun saveServiceCredentials(clientId: String, clientSecret: String) {
        prefs.edit()
            .putString("cf_client_id", clientId)
            .putString("cf_client_secret", clientSecret)
            .apply()
    }

    val clientId: String?
        get() = prefs.getString("cf_client_id", null)

    val clientSecret: String?
        get() = prefs.getString("cf_client_secret", null)

    fun hasValidCredentials(): Boolean {
        return !clientId.isNullOrBlank() && !clientSecret.isNullOrBlank()
    }
}
```

#### B. Cloudflare Access Header Interceptor (`CloudflareAccessInterceptor.kt`)

```kotlin
package com.bimax.mobile.data.network

import com.bimax.mobile.security.TokenStore
import okhttp3.Interceptor
import okhttp3.Response
import java.io.IOException

class CloudflareAccessInterceptor(
    private val tokenStore: TokenStore
) : Interceptor {

    @Throws(IOException::class)
    override fun intercept(chain: Interceptor.Chain): Response {
        val originalRequest = chain.request()

        val clientId = tokenStore.clientId
        val clientSecret = tokenStore.clientSecret

        if (clientId.isNullOrBlank() || clientSecret.isNullOrBlank()) {
            throw IOException("Missing Cloudflare Access credentials. Please pair device via QR code.")
        }

        // Dynamically inject Cloudflare Access headers into the HTTP / WebSocket upgrade request
        val authenticatedRequest = originalRequest.newBuilder()
            .header("CF-Access-Client-Id", clientId)
            .header("CF-Access-Client-Secret", clientSecret)
            .header("User-Agent", "BimaxMobile/1.0 (Android; Snapdragon 8 Elite)")
            .build()

        val response = chain.proceed(authenticatedRequest)

        // Detect Edge Authentication Failure (401 with WWW-Authenticate)
        if (response.code == 401) {
            val authHeader = response.header("WWW-Authenticate")
            if (authHeader != null && authHeader.contains("invalid_token")) {
                throw CloudflareAuthException("Cloudflare Access Edge rejected Service Token: $authHeader")
            }
        }

        return response
    }
}

class CloudflareAuthException(message: String) : IOException(message)
```

#### C. Connecting OkHttp WebSocket with the Interceptor

```kotlin
package com.bimax.mobile.data.network

import android.content.Context
import com.bimax.mobile.security.TokenStore
import okhttp3.*
import java.util.concurrent.TimeUnit

fun createBimaxHttpClient(context: Context): OkHttpClient {
    val tokenStore = TokenStore(context)

    return OkHttpClient.Builder()
        .addInterceptor(CloudflareAccessInterceptor(tokenStore))
        .pingInterval(25, TimeUnit.SECONDS)
        .connectTimeout(10, TimeUnit.SECONDS)
        .readTimeout(0, TimeUnit.MILLISECONDS) // Indefinite read for persistent streams
        .retryOnConnectionFailure(true)
        .build()
}
```

### 4. Edge Rejection Behavior: What Fails Look Like

When an unauthenticated request or expired token hits the Cloudflare edge, Cloudflare drops it before touching the Mac:

```http
HTTP/1.1 401 Unauthorized
Date: Tue, 22 Sep 2026 00:25:00 GMT
Content-Type: application/json
Content-Length: 94
Connection: keep-alive
WWW-Authenticate: Bearer realm="OAuth", error="invalid_token", error_description="Missing or invalid access token", resource_metadata="https://bimax-bridge.yourdomain.com/.well-known/cloudflare-access-protected-resource/"
CF-Ray: 923847a01c8a1234-BOM
Server: cloudflare

{"error": "invalid_token", "error_description": "Missing or invalid access token"}
```

In OkHttp, this triggers `WebSocketListener.onFailure(webSocket, t, response)`, where `response.code` equals `401`. The Android app can immediately display:  
*"Service Token Rejected by Cloudflare Edge. Re-scan pairing QR code."*

### 5. Instant Verification CLI Scripts

Before running on Android, verify your Service Token directly from your macOS terminal using `curl` and `wscat`:

```bash
# 1. Export credentials from Cloudflare Dashboard
export CF_CLIENT_ID="your-client-id.access"
export CF_CLIENT_SECRET="your-client-secret-hex"
export TARGET_HOST="https://bimax-bridge.yourdomain.com"

# 2. Test unauthenticated request (MUST return 401 Unauthorized)
curl -I "$TARGET_HOST"
# Expected output: HTTP/2 401, WWW-Authenticate: Bearer ...

# 3. Test authenticated request with Service Token (MUST pass through to Mac)
curl -I "$TARGET_HOST" \
  -H "CF-Access-Client-Id: $CF_CLIENT_ID" \
  -H "CF-Access-Client-Secret: $CF_CLIENT_SECRET"
# Expected output: HTTP/2 200 (or origin response)

# 4. Test WebSocket upgrade with Service Token
wscat -c "wss://bimax-bridge.yourdomain.com/ws" \
  -H "CF-Access-Client-Id: $CF_CLIENT_ID" \
  -H "CF-Access-Client-Secret: $CF_CLIENT_SECRET"
```
