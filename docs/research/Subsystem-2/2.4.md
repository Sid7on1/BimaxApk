# Subsystem 2: End-to-End Cryptography (E2EE) & Hardware Keystore
## Research Dossier 2.4: Anti-Replay, Message Sequencing & Monotonic Nonce Management

> **Verification Status**: `VERIFIED: PASS`  
> **Audited By**: Bimax Architecture Core  
> **Domain**: RFC 4303 / RFC 6479 Anti-Replay Architecture, AEAD Associated Data (AAD), 1024-Bit Sliding Window, Two-Tier Desync Recovery  
> **Target Environment**: macOS Host $\leftrightarrow$ Untrusted Network / Relays $\leftrightarrow$ Android Client

### 1. Verification Summary & Threat Model

Even with authenticated encryption (AEAD), an attacker eavesdropping on the network could record previously transmitted encrypted command frames (e.g. an encrypted approval frame for `git push --force` or `rm -rf ./build`) and re-inject them hours or days later over the WebSocket connection.

To mathematically eliminate this attack surface:
1. **AEAD Nonce Uniqueness & Associated Data (AAD)**:
   - ChaCha20-Poly1305 requires that the $(Key, Nonce)$ pair is **never reused**.
   - **Critical Rule**: The entire binary header (`seq_no`, `timestamp_ms`, `payload_type`, `session_id`) is passed as **Associated Data (AD)** to the AEAD decryptor. If an attacker modifies the sequence number or session ID, the Poly1305 tag verification fails **before** the anti-replay window is updated.
2. **64-bit Monotonic Counters**:
   - Every outbound payload strictly increments a $64$-bit integer ($1, 2, 3, \dots, 2^{64}-1$). Counters are independent per direction (`client -> host` vs. `host -> client`) and are scoped strictly to a specific `session_id`.
3. **Scaled 1024-Bit Sliding Window Bitmap Filter**:
   - PTY terminal streaming (`PTYChunk`) generates high packet throughput (hundreds of chunks/second during builds or test runs). While a 64-packet window is sufficient for low-rate commands, mobile 5G/Wi-Fi packet reordering requires a **1024-packet sliding window ($W = 1024$)** to eliminate false-positive drops.
4. **Timestamp Freshness Bounds**:
   - Packets older than **5 minutes ($300,000\text{ ms}$)** or in the future by $>30\text{ seconds}$ (clock skew) are rejected even if nominally within sequence limits.
5. **Two-Tier Desynchronization Recovery**:
   - **Tier 1 (Soft Recovery)**: `ResyncRequest` (0x40) / `ResyncAck` (0x41) control handshake with nonce verification.
   - **Tier 2 (Hard Recovery)**: `SessionReset` (0x42) tearing down the session and executing a fresh 1-RTT Noise handshake.

### 2. Binary Wire Header Specification (AEAD Associated Data)

Every payload transmitted inside the E2EE stream begins with this **35-byte binary header**:

```
+--------------------+--------------------+--------------------+---------------------+
| Version (1 Byte)   | Payload Type (1B)  | Sequence ID (8B)   | Timestamp (8 Bytes) |
| uint8 = 0x01       | uint8 enum         | uint64 BigEndian   | int64 Unix Millis   |
+--------------------+--------------------+--------------------+---------------------+
| Session UUID (16 Bytes)                 | Header Length (1B) | Ciphertext + Tag    |
| 128-bit session identifier              | uint8 = 35         | N Bytes + 16B Tag   |
+-----------------------------------------+--------------------+---------------------+
```

| Field | Size | Data Type | Description |
| :--- | :--- | :--- | :--- |
| `version` | $1\text{ byte}$ | `uint8` | Protocol version (`0x01`). |
| `payload_type` | $1\text{ byte}$ | `uint8` | `0x01`: ShellCommand, `0x02`: ApprovalReq, `0x03`: ApprovalAck, `0x10`: PTYChunk, `0x40`: ResyncReq, `0x41`: ResyncAck, `0x42`: SessionReset. |
| `seq_no` | $8\text{ bytes}$ | `uint64_be` | Monotonic counter starting at 1. |
| `timestamp_ms` | $8\text{ bytes}$ | `int64_be` | Unix epoch in milliseconds. |
| `session_id` | $16\text{ bytes}$ | `raw bytes` | Ephemeral 128-bit UUID generated during key exchange. |
| `header_len` | $1\text{ byte}$ | `uint8` | Fixed length byte ($35$) for sanity check. |

### 3. Production 1024-Bit Sliding Window Replay Filter (Go Implementation)

This implementation maintains a **1024-bit window** using sixteen 64-bit unsigned integers (`[16]uint64`), executing in $O(1)$ constant time:

```go
package crypto

import (
	"encoding/binary"
	"errors"
	"sync"
	"time"
)

const (
	WindowSize    = 1024 // 1024-packet tracking window for high-throughput PTY streaming
	WordsInWindow = WindowSize / 64
	MaxTimeSkewMs = 300000 // 5 minutes max age
)

var (
	ErrReplayDetected = errors.New("packet rejected: duplicate or replayed sequence number")
	ErrPacketTooOld   = errors.New("packet rejected: sequence number falls behind sliding window")
	ErrStaleTimestamp = errors.New("packet rejected: timestamp older than 5 minutes")
	ErrFutureClock    = errors.New("packet rejected: timestamp significantly in the future")
)

type ReplayWindow struct {
	mu     sync.Mutex
	maxSeq uint64
	bitmap [WordsInWindow]uint64
}

func NewReplayWindow() *ReplayWindow {
	return &ReplayWindow{
		maxSeq: 0,
	}
}

// ValidateTimestamp verifies freshness against local system clock
func ValidateTimestamp(timestampMs int64) error {
	nowMs := time.Now().UnixMilli()
	diff := nowMs - timestampMs

	if diff > MaxTimeSkewMs {
		return ErrStaleTimestamp
	}
	if diff < -30000 { // > 30s in the future
		return ErrFutureClock
	}
	return nil
}

// CheckAndCommit verifies that sequence is valid and updates the window ONLY AFTER AEAD tag passes
func (rw *ReplayWindow) CheckAndCommit(seq uint64) error {
	rw.mu.Lock()
	defer rw.mu.Unlock()

	// Initial packet
	if rw.maxSeq == 0 {
		rw.maxSeq = seq
		rw.bitmap[0] = 1
		return nil
	}

	if seq > rw.maxSeq {
		// Advance window right
		diff := seq - rw.maxSeq
		if diff < WindowSize {
			rw.shiftRight(diff)
			rw.setBit(0) // Mark newest bit
		} else {
			// Jump exceeded entire window: reset bitmap and mark bit 0
			for i := range rw.bitmap {
				rw.bitmap[i] = 0
			}
			rw.bitmap[0] = 1
		}
		rw.maxSeq = seq
		return nil
	}

	// Packet is older than maxSeq
	diff := rw.maxSeq - seq
	if diff >= WindowSize {
		return ErrPacketTooOld
	}

	// Check if already seen
	if rw.isBitSet(diff) {
		return ErrReplayDetected
	}

	// Mark bit as seen within window
	rw.setBit(diff)
	return nil
}

func (rw *ReplayWindow) setBit(diff uint64) {
	wordIndex := diff / 64
	bitIndex := diff % 64
	rw.bitmap[wordIndex] |= (uint64(1) << bitIndex)
}

func (rw *ReplayWindow) isBitSet(diff uint64) bool {
	wordIndex := diff / 64
	bitIndex := diff % 64
	return (rw.bitmap[wordIndex] & (uint64(1) << bitIndex)) != 0
}

func (rw *ReplayWindow) shiftRight(shift uint64) {
	wordShift := shift / 64
	bitShift := shift % 64

	if wordShift >= WordsInWindow {
		for i := range rw.bitmap {
			rw.bitmap[i] = 0
		}
		return
	}

	// Shift words
	for i := WordsInWindow - 1; i >= int(wordShift); i-- {
		rw.bitmap[i] = rw.bitmap[i-int(wordShift)]
	}
	for i := 0; i < int(wordShift); i++ {
		rw.bitmap[i] = 0
	}

	// Shift remaining bits across word boundaries
	if bitShift > 0 {
		var carry uint64
		for i := 0; i < WordsInWindow; i++ {
			newCarry := rw.bitmap[i] >> (64 - bitShift)
			rw.bitmap[i] = (rw.bitmap[i] << bitShift) | carry
			carry = newCarry
		}
	}
}
```

### 4. Two-Tier Desynchronization Recovery State Machine

```
                        [ NORMAL OPERATION ]
                                 │
           Consecutive Auth Fails > 16 OR SeqJump > W
                                 │
                                 ▼
                     [ DESYNC_SUSPECTED ]
                     (Freeze App Payloads)
                                 │
                     Send ResyncRequest (0x40)
                                 │
                       Receive ResyncAck (0x41)
                                / \
                 Delta <= W    /   \   Delta > W or Nonce Mismatch
                              /     \
                             ▼       ▼
               [ REBUILD WINDOW ]   [ SESSION_RESET (0x42) ]
               Return to NORMAL     Trigger Fresh 1-RTT Handshake
```

#### A. Desync Trigger Conditions
1. **Sequence Jump**: $\text{seq\_no} > \text{max\_seq} + W$ (indicates missed batch or network state loss).
2. **Consecutive Integrity Failures**: $>16$ consecutive packets fail AEAD decryption (indicates counter misalignment).
3. **Clock Skew Failure**: Timestamps consistently diverge from system clock.

#### B. Resync Handshake Control Payloads
1. **`ResyncRequest` (Payload Type `0x40`)**:
   - `session_id` ($16$ bytes)
   - `daemon_max_seq` ($8$ bytes)
   - `resync_nonce` ($16$ bytes random salt)
2. **`ResyncAck` (Payload Type `0x41`)**:
   - `session_id` ($16$ bytes)
   - `client_max_seq` ($8$ bytes)
   - `resync_nonce` ($16$ bytes echoed back)

If $\text{client\_max\_seq} - \text{daemon\_max\_seq} \le 1024$, the daemon sets $\text{max\_seq} = \text{client\_max\_seq}$, zeroes the bitmap, and resumes normal execution. Otherwise, it issues **`SessionReset` (0x42)**, forcing a clean re-key.

### 5. Android Client: Sequence Manager with AAD Framing (Kotlin)

```kotlin
package com.bimax.mobile.security

import java.nio.ByteBuffer
import java.nio.ByteOrder
import java.util.UUID
import java.util.concurrent.atomic.AtomicLong

class OutboundSequenceManager(private val sessionId: UUID) {
    private val counter = AtomicLong(1L)

    fun buildAuthenticatedHeader(payloadType: Byte): Pair<ByteArray, Long> {
        val seq = counter.getAndIncrement()
        val nowMs = System.currentTimeMillis()

        val headerBytes = ByteBuffer.allocate(35)
            .order(ByteOrder.BIG_ENDIAN)
            .put(0x01.toByte())          // Version 1
            .put(payloadType)            // Payload type enum
            .putLong(seq)                // 64-bit monotonic sequence counter
            .putLong(nowMs)              // 64-bit epoch millis
            .putLong(sessionId.mostSignificantBits)
            .putLong(sessionId.leastSignificantBits)
            .put(35.toByte())            // Header length
            .array()

        return Pair(headerBytes, seq)
    }

    fun reset() {
        counter.set(1L)
    }
}
```
