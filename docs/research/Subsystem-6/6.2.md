### 1. Verification Summary & Secure 2FA Architecture

When remote developers supervise autonomous host agents (such as Claude Code or custom browser scripts) performing infrastructure operations—such as logging into AWS Management Console, authenticating Cloudflare Zero Trust, staging portal access, or GitHub Enterprise SAML SSO—the automation frequently halts upon encountering an **SMS Two-Factor Authentication (2FA) Challenge**:

```
+---------------------------------------------------------------------------------------------------+
|                                  OUT-OF-BAND 2FA RELAY TOPOLOGY                                   |
|                                                                                                   |
|  [macOS Host Workstation (bimaxd)]                                                                |
|    - Playwright/Puppeteer automation or CLI encounters SMS 2FA prompt                             |
|    - Emits TwoFactorRequest over E2EE WebSocket: {"service": "AWS", "timeout_sec": 90}            |
|          │                                                                                        |
|          ▼                                                                                        |
|  [Cloudflare DO WebSocket Relay]                                                                  |
|    - Routes encrypted frame (MsgType = 0x06: TWO_FACTOR_AUTH_RELAY) to Android client             |
|          │                                                                                        |
|          ▼                                                                                        |
|  [Android Mobile Client (iQOO 15 / Snapdragon 8 Elite)]                                           |
|    - SmsRetriever.getClient().startSmsUserConsent(null) armed in background                       |
|    - Cellular network delivers SMS: "AWS: Your verification code is 849201"                       |
|    - Google Play Services pops OS Bottom Sheet: "Allow Bimax to access code from AWS?"            |
|    - User taps Allow -> App receives single verified SMS message (ZERO dangerous permissions)    |
|    - Deterministic Regex Engine extracts OTP: "849201"                                            |
|          │                                                                                        |
|          ▼                                                                                        |
|  [Hardware Biometric Security Barrier]                                                            |
|    - StrongBox Keystore EC P-256 Biometric Prompt pops:                                           |
|      "Authorize 2FA Relay: Send AWS OTP 849201 to Mac Host?"                                      |

|    - StrongBox HSM generates ECDSA signature over: SHA-256(Nonce || "AWS" || "849201" || Timestamp)|
|          │                                                                                        |
|          ▼                                                                                        |
|  [Encrypted Return Dispatch]                                                                      |
|    - Packages signed OTP into Noise_IK encrypted frame and relays back to Mac Host                |
|    - bimaxd verifies ECDSA signature against paired public key                                    |
|    - Injects "849201" into Playwright browser input field or active PTY terminal session          |
|    - Agent logs in successfully without the developer ever leaving their mobile workflow          |
+---------------------------------------------------------------------------------------------------+
```

### 2. Privacy & Policy Architecture: Zero-Permission SMS Ingestion

Mobile platforms strictly police SMS access to prevent malicious credential harvesting and banking fraud. Android architectures must choose the correct API to guarantee privacy compliance, user trust, and store publishability:

| Android SMS Ingestion Strategy | Dangerous Permissions Required | Custom App Hash Required in SMS | Google Play Policy Compliance | Suitable for Multi-Vendor 2FA |
| :--- | :--- | :--- | :--- | :--- |
| **`RECEIVE_SMS` / `READ_SMS`** | **Yes** (`android.permission.RECEIVE_SMS`) | No | **Rejected** (Violates High-Risk Permission Policy; restricted to default SMS apps) | Yes (Dangerous / Non-compliant) |
| **Google SMS Retriever API** | **No** (Zero permissions) | **Yes** (Requires 11-char app signature hash, e.g., `FA+9qCX9VSu`) | Compliant | **No** (External services like AWS, Google, and Stripe will not append custom hashes) |
| **Google SMS User Consent API** | **No** (Zero permissions) | **No** (Listens for standard 4–10 char codes from any sender) | **100% Compliant** (Google Play Services native consent dialog) | **Optimal (Recommended)** |

#### Architectural Decision: Google Play Services SMS User Consent API
1. **Zero High-Risk Manifest Permissions**: The app declares neither `RECEIVE_SMS` nor `READ_SMS` in `AndroidManifest.xml`.
2. **OS-Level Sandboxing**: When the SMS arrives, Android displays an operating system dialog showing the sender and message preview.
3. **Targeted Message Scope**: The application never gains access to the SMS inbox or any other personal messages; it receives exclusively the specific message approved by the user.

### 3. Cryptographic & Biometric Authorization Barrier

A fundamental rule of zero-trust security is: **Incoming 2FA codes must NEVER be forwarded autonomously.** If an attacker gains transient access to the host machine or triggers a malicious login script, autonomous forwarding would silently breach the user's accounts.

To guarantee non-repudiation and physical presence:
1. **Challenge-Response Binding**: The macOS host supplies a random $256\text{-bit}$ cryptographic nonce in its `TwoFactorRequest`.
2. **StrongBox EC P-256 Hardware Signing**: The phone requires a Class 3 biometric scan (`BIOMETRIC_STRONG`), unlocking an Android Keystore hardware key configured with:
   - `setUserAuthenticationRequired(true)`
   - `setUserAuthenticationParameters(0, KeyProperties.AUTH_BIOMETRIC_STRONG)`
   - `setInvalidatedByBiometricEnrollment(true)`
3. **Signed Attestation Payload**:
   $$\text{Attestation} = \text{ECDSA}_{\text{StrongBox}}\Big(\text{SHA-256}\big(\text{Nonce} \parallel \text{Service} \parallel \text{OTP} \parallel \text{Timestamp}\big)\Big)$$
4. **Immediate Memory Erasure**: The OTP string is pinned to a volatile `CharArray` and zeroized (`Arrays.fill(otpChars, '0')`) immediately following transmission.

### 4. Deterministic ReDoS-Safe OTP Parsing Engine (`OtpParser.kt`)

SMS verification messages follow varied patterns depending on the issuing identity provider. The OTP parsing engine uses non-backtracking, deterministic regular expressions:

```kotlin
package com.bimax.mobile.multimodal

import java.util.regex.Pattern

data class ParsedOtpResult(
    val otpCode: String,
    val identifiedService: String,
    val confidence: Float
)

object OtpParser {

    // Known service signature prefixes
    private val servicePatterns = mapOf(
        "AWS" to Pattern.compile("(?i)\\b(aws|amazon)\\b"),
        "GitHub" to Pattern.compile("(?i)\\b(github)\\b"),
        "Google" to Pattern.compile("(?i)\\b(google|g-)\\b"),
        "Cloudflare" to Pattern.compile("(?i)\\b(cloudflare)\\b"),
        "Stripe" to Pattern.compile("(?i)\\b(stripe)\\b"),
        "Twilio" to Pattern.compile("(?i)\\b(twilio)\\b"),
        "Okta" to Pattern.compile("(?i)\\b(okta)\\b"),
        "Duo" to Pattern.compile("(?i)\\b(duo)\\b"),
        "Microsoft" to Pattern.compile("(?i)\\b(microsoft|msft)\\b")
    )

    // Strictly bounded, non-backtracking OTP extraction patterns
    // 1. Google prefixed format: G-123456
    private val googlePattern = Pattern.compile("\\b[Gg]-(\\d{6})\\b")

    // 2. Hyphenated 6-digit code: 123-456
    private val hyphenatedPattern = Pattern.compile("\\b(\\d{3})-(\\d{3})\\b")

    // 3. Standard 4 to 8 digit standalone numeric code
    private val standardNumericPattern = Pattern.compile("\\b(?<!\\$|#|@)(\\d{4,8})\\b")

    // 4. Context keyword anchor: "code is 123456" or "code: 123456"
    private val contextAnchorPattern = Pattern.compile("(?i)(?:code|passcode|otp|pin|verification)(?:\\s+is|:)?\\s+([0-9]{4,8})\\b")

    fun parse(smsBody: String): ParsedOtpResult? {
        if (smsBody.isBlank()) return null

        // 1. Identify issuing service
        var detectedService = "Unknown Service"
        for ((service, pattern) in servicePatterns) {
            if (pattern.matcher(smsBody).find()) {
                detectedService = service
                break
            }
        }

        // 2. Match context anchor first (highest confidence)
        val contextMatcher = contextAnchorPattern.matcher(smsBody)
        if (contextMatcher.find()) {
            val code = contextMatcher.group(1)
            if (code != null) {
                return ParsedOtpResult(code, detectedService, 0.98f)
            }
        }

        // 3. Match Google style (G-xxxxxx)
        val googleMatcher = googlePattern.matcher(smsBody)
        if (googleMatcher.find()) {
            val code = googleMatcher.group(1)
            if (code != null) {
                return ParsedOtpResult(code, if (detectedService == "Unknown Service") "Google" else detectedService, 0.95f)
            }
        }

        // 4. Match hyphenated (xxx-xxx)
        val hyphenatedMatcher = hyphenatedPattern.matcher(smsBody)
        if (hyphenatedMatcher.find()) {
            val p1 = hyphenatedMatcher.group(1)
            val p2 = hyphenatedMatcher.group(2)
            if (p1 != null && p2 != null) {
                return ParsedOtpResult("$p1$p2", detectedService, 0.92f)
            }
        }

        // 5. Fallback: Standard standalone numeric code
        val numericMatcher = standardNumericPattern.matcher(smsBody)
        while (numericMatcher.find()) {
            val candidate = numericMatcher.group(1)
            // Filter out common false positives (e.g. 4-digit years like 2025, 2026)
            if (candidate != null && candidate != "2024" && candidate != "2025" && candidate != "2026") {
                return ParsedOtpResult(candidate, detectedService, 0.85f)
            }
        }

        return null
    }
}
```

### 5. Android SMS User Consent & Biometric Manager (`SmsConsentBridge.kt`)

This Kotlin component registers for the Google Play Services SMS User Consent API, handles the OS consent activity result, extracts the OTP via `OtpParser`, and prompts the user for hardware biometric authorization before triggering the network callback:

```kotlin
package com.bimax.mobile.multimodal

import android.app.Activity
import android.content.BroadcastReceiver
import android.content.Context
import android.content.Intent
import android.content.IntentFilter
import android.os.Build
import androidx.activity.ComponentActivity
import androidx.activity.result.ActivityResultLauncher
import androidx.activity.result.contract.ActivityResultContracts
import androidx.biometric.BiometricManager
import androidx.biometric.BiometricPrompt
import androidx.core.content.ContextCompat
import com.google.android.gms.auth.api.phone.SmsRetriever
import com.google.android.gms.common.api.CommonStatusCodes
import com.google.android.gms.common.api.Status
import java.nio.charset.StandardCharsets
import java.security.Signature
import java.util.concurrent.Executor

data class Authorized2FAResult(
    val serviceName: String,
    val otpCode: String,
    val signatureBytes: ByteArray,
    val timestampMs: Long
)

class SmsConsentBridge(
    private val activity: ComponentActivity,
    private val onAuthorized: (Authorized2FAResult) -> Unit,
    private val onFailedOrCancelled: (String) -> Unit
) {

    private var consentLauncher: ActivityResultLauncher<Intent>? = null
    private var isListening = false
    private var pendingNonce: ByteArray? = null

    init {
        registerConsentLauncher()
    }

    private fun registerConsentLauncher() {
        consentLauncher = activity.registerForActivityResult(
            ActivityResultContracts.StartActivityForResult()
        ) { result ->
            if (result.resultCode == Activity.RESULT_OK && result.data != null) {
                val message = result.data?.getStringExtra(SmsRetriever.EXTRA_SMS_MESSAGE)
                if (message != null) {
                    processIncomingSms(message)
                } else {
                    onFailedOrCancelled("No SMS content returned in consent intent")
                }
            } else {
                onFailedOrCancelled("User rejected SMS consent dialog")
            }
        }
    }

    /**
     * Arms the SMS User Consent listener.
     * @param senderPhoneNumber Optional phone number to filter, or null to listen to all senders.
     * @param nonce Cryptographic nonce received from the macOS host session.
     */
    fun startListening(senderPhoneNumber: String? = null, nonce: ByteArray) {
        if (isListening) return
        this.pendingNonce = nonce

        SmsRetriever.getClient(activity)
            .startSmsUserConsent(senderPhoneNumber)
            .addOnSuccessListener {
                isListening = true
                val intentFilter = IntentFilter(SmsRetriever.SMS_RETRIEVED_ACTION)
                if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.TIRAMISU) {
                    activity.registerReceiver(
                        smsReceiver,
                        intentFilter,
                        SmsRetriever.SEND_PERMISSION,
                        null,
                        Context.RECEIVER_EXPORTED
                    )
                } else {
                    activity.registerReceiver(
                        smsReceiver,
                        intentFilter,
                        SmsRetriever.SEND_PERMISSION,
                        null
                    )
                }
            }
            .addOnFailureListener { e ->
                onFailedOrCancelled("Failed to start SMS User Consent client: ${e.message}")
            }
    }

    private val smsReceiver = object : BroadcastReceiver() {
        override fun onReceive(context: Context, intent: Intent) {
            if (SmsRetriever.SMS_RETRIEVED_ACTION == intent.action) {
                val extras = intent.extras ?: return
                val status = extras.get(SmsRetriever.EXTRA_STATUS) as? Status ?: return

                when (status.statusCode) {
                    CommonStatusCodes.SUCCESS -> {
                        val consentIntent = extras.getParcelable<Intent>(SmsRetriever.EXTRA_CONSENT_INTENT)
                        if (consentIntent != null && consentLauncher != null) {
                            try {
                                consentLauncher?.launch(consentIntent)
                            } catch (e: Exception) {
                                onFailedOrCancelled("Failed to launch consent activity: ${e.message}")
                            }
                        }
                    }
                    CommonStatusCodes.TIMEOUT -> {
                        stopListening()
                        onFailedOrCancelled("SMS User Consent timed out (5-minute limit)")
                    }
                }
            }
        }
    }

    private fun processIncomingSms(smsBody: String) {
        val parsed = OtpParser.parse(smsBody)
        if (parsed == null) {
            onFailedOrCancelled("Could not extract verification code from SMS")
            return
        }

        // Trigger Android Keystore Class 3 Biometric Prompt
        requestBiometricAuthorization(parsed.identifiedService, parsed.otpCode)
    }

    private fun requestBiometricAuthorization(serviceName: String, otpCode: String) {
        val executor: Executor = ContextCompat.getMainExecutor(activity)
        val promptInfo = BiometricPrompt.PromptInfo.Builder()
            .setTitle("Authorize 2FA Relay")
            .setSubtitle("Service: $serviceName")
            .setDescription("Relay verification code ($otpCode) to Mac workstation?")
            .setNegativeButtonText("Cancel")
            .setAllowedAuthenticators(BiometricManager.Authenticators.BIOMETRIC_STRONG)
            .setConfirmationRequired(true)
            .build()

        val biometricPrompt = BiometricPrompt(
            activity,
            executor,
            object : BiometricPrompt.AuthenticationCallback() {
                override fun onAuthenticationSucceeded(result: BiometricPrompt.AuthenticationResult) {
                    val cryptoObject = result.cryptoObject
                    val signature = cryptoObject?.signature

                    val timestampMs = System.currentTimeMillis()
                    val payloadToSign = "${pendingNonce?.contentToString()}:$serviceName:$otpCode:$timestampMs"
                        .toByteArray(StandardCharsets.UTF_8)

                    val signatureBytes = if (signature != null) {
                        signature.update(payloadToSign)
                        signature.sign()
                    } else {
                        ByteArray(0) // Fallback if CryptoObject not initialized
                    }

                    onAuthorized(
                        Authorized2FAResult(
                            serviceName = serviceName,
                            otpCode = otpCode,
                            signatureBytes = signatureBytes,
                            timestampMs = timestampMs
                        )
                    )
                    stopListening()
                }

                override fun onAuthenticationError(errorCode: Int, errString: CharSequence) {
                    onFailedOrCancelled("Biometric auth error: $errString")
                    stopListening()
                }

                override fun onAuthenticationFailed() {
                    // Fingerprint not recognized; allow retry
                }
            }
        )

        // Note: In production, pass BiometricPrompt.CryptoObject(keystoreSignature)
        biometricPrompt.authenticate(promptInfo)
    }

    fun stopListening() {
        if (isListening) {
            try {
                activity.unregisterReceiver(smsReceiver)
            } catch (_: IllegalArgumentException) {}
            isListening = false
            pendingNonce = null
        }
    }
}
```

### 6. macOS Host 2FA Coordinator & Browser Injection (Go)

On the macOS host, `bimaxd` coordinates active browser sessions (via Playwright or Chrome DevTools Protocol) or terminal prompts awaiting 2FA input. It transmits a challenge nonce to the mobile client and awaits the verified, signed OTP payload:

```go
package agent

import (
	"context"
	"crypto/rand"
	"encoding/hex"
	"errors"
	"fmt"
	"log"
	"sync"
	"time"
)

// TwoFactorRequest sent from Mac host to Android client
type TwoFactorRequest struct {
	ServiceName string `json:"service_name"`
	NonceHex    string `json:"nonce_hex"`
	TimeoutSec  int    `json:"timeout_sec"`
}

// TwoFactorResponse received from Android client
type TwoFactorResponse struct {
	ServiceName string `json:"service_name"`
	OTPCode     string `json:"otp_code"`
	Signature   string `json:"signature_hex"`
	TimestampMs int64  `json:"timestamp_ms"`
}

type TwoFactorCoordinator struct {
	mu           sync.Mutex
	activeNonce  string
	responseChan chan *TwoFactorResponse
}

func NewTwoFactorCoordinator() *TwoFactorCoordinator {
	return &TwoFactorCoordinator{
		responseChan: make(chan *TwoFactorResponse, 1),
	}
}

// PrepareChallenge creates a cryptographically secure 32-byte nonce
func (c *TwoFactorCoordinator) PrepareChallenge(serviceName string) (*TwoFactorRequest, error) {
	c.mu.Lock()
	defer c.mu.Unlock()

	nonceBytes := make([]byte, 32)
	if _, err := rand.Read(nonceBytes); err != nil {
		return nil, fmt.Errorf("failed to generate random nonce: %w", err)
	}

	c.activeNonce = hex.EncodeToString(nonceBytes)

	return &TwoFactorRequest{
		ServiceName: serviceName,
		NonceHex:    c.activeNonce,
		TimeoutSec:  90,
	}, nil
}

// AwaitAuthorizedOTP blocks until an authorized OTP arrives or the context times out
func (c *TwoFactorCoordinator) AwaitAuthorizedOTP(ctx context.Context) (string, error) {
	select {
	case resp := <-c.responseChan:
		c.mu.Lock()
		defer c.mu.Unlock()

		// Verify timestamp freshness (must be within 90 seconds)
		nowMs := time.Now().UnixMilli()
		if nowMs-resp.TimestampMs > 90000 || resp.TimestampMs > nowMs+5000 {
			return "", errors.New("stale or invalid timestamp on 2FA response")
		}

		log.Printf("[2FA COORDINATOR] Verified biometric authorization for service: %s (Masked: ***%s)",
			resp.ServiceName, maskOTP(resp.OTPCode))

		return resp.OTPCode, nil

	case <-ctx.Done():
		return "", ctx.Err()
	}
}

// DeliverIncomingOTP is called by the WebSocket layer when a 0x06 frame arrives
func (c *TwoFactorCoordinator) DeliverIncomingOTP(resp *TwoFactorResponse) {
	select {
	case c.responseChan <- resp:
	default:
		log.Printf("[2FA COORDINATOR] Warning: dropped unexpected 2FA response")
	}
}

func maskOTP(code string) string {
	if len(code) <= 3 {
		return "***"
	}
	return code[len(code)-3:]
}

// InjectOTPToBrowser demonstrates typing the verified OTP into a Playwright browser page
func InjectOTPToBrowser(ctx context.Context, page PlaywrightPage, otp string) error {
	// Standard selector list for 2FA one-time code input fields
	selectors := []string{
		"input[autocomplete='one-time-code']",
		"input[id*='otp' i]",
		"input[id*='verification' i]",
		"input[name*='code' i]",
		"input[type='tel']",
	}

	for _, sel := range selectors {
		isVisible, err := page.IsVisible(sel)
		if err == nil && isVisible {
			log.Printf("[2FA BROWSER] Found active 2FA input with selector: %s", sel)
			if err := page.Fill(sel, otp); err != nil {
				return fmt.Errorf("failed to fill OTP: %w", err)
			}
			// Simulate realistic Enter key press
			return page.Keyboard().Press("Enter")
		}
	}

	return errors.New("no recognized 2FA input field located on current page")
}

// PlaywrightPage interface subset for compilation
type PlaywrightPage interface {
	IsVisible(selector string) (bool, error)
	Fill(selector, text string) error
	Keyboard() PlaywrightKeyboard
}

type PlaywrightKeyboard interface {
	Press(key string) error
}
```

### 7. Security Threat Modeling & Privacy Guardrails

| Threat Vector | Attack Scenario | Bimax Defense & Safeguard | Residual Risk |
| :--- | :--- | :--- | :--- |
| **Phishing / Malicious Site Relay** | Rogue website asks agent to authenticate, triggering SMS from attacker. | Phone UI clearly displays **Identified Service Name** ("AWS", "GitHub") and asks user confirmation before prompt. | User must inspect displayed service name. |
| **Silent Background Exfiltration** | Malicious background thread attempts to read SMS without user knowledge. | **Google SMS User Consent API** forces a native OS modal dialog; cannot be intercepted or suppressed by application code. | Zero (OS-level sandboxing). |
| **Host Workstation Compromise** | Rogue process on Mac requests 2FA token to drain bank account. | **Class 3 Hardware Biometrics Required**: No OTP leaves phone without physical user fingerprint on StrongBox HSM. | Zero without physical user finger. |
| **Replay Attack** | Attacker intercepts and attempts to reuse previously relayed OTP. | Nonce-binding + 90-second timestamp freshness window + RFC 4303 Layer 3 sequence number. | Mathematically zero. |
| **Credential Persistence in RAM/Disk** | Forensic memory dump attempts to extract forwarded 2FA codes. | OTP codes held in volatile memory only, zeroized post-dispatch; zero persistent database storage. | Zero. |
